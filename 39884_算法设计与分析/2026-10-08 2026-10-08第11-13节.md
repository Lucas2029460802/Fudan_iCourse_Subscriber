### 均摊分析

均摊分析是一种与传统最坏情况分析、平均情况分析不同的算法分析方法。传统的最坏情况分析关注单次操作的最坏开销，平均情况分析关注对随机输入的平均开销。而均摊分析则关注对**任意的一系列操作**，**平均到每一次操作的开销是多少**。它的核心思想是：在某个数据结构或算法中，大部分操作可能非常便宜，但偶尔会出现一次开销极大的操作。我们不能单看这个昂贵操作，而应该将它的开销均摊到整个操作序列中去，从整体上评估算法的性能。

均摊分析主要有三种等价的分析方法，它们从不同角度看待同一问题，本质上都是在计算一系列操作的平均摊还成本。

#### 聚合法

聚合法的思想最直观：先计算连续 $m$ 次操作的总成本 $T(m)$，再平均到每次操作，得到均摊成本 $T(m)/m$。这种方法不给不同操作分配不同的代价，而是统一一种均摊代价。关键在于如何精确计算整个操作序列的总代价。

##### 栈操作分析

考虑一个支持三种操作的栈：
*   $\text{Push}(S, x)$：将元素 $x$ 压栈，代价为 $O(1)$。
*   $\text{Pop}(S)$：弹出栈顶元素，代价为 $O(1)$。
*   $\text{Multipop}(S, k)$：持续弹出栈顶元素直到弹出 $k$ 个元素或栈为空，其实际代价为 $\min(|S|, k)$。

如果进行粗略分析，一个最坏情况是一个 $\text{Multipop}$ 操作的代价为 $O(n)$，那么连续 $n$ 次操作的最坏总代价似乎是 $O(n^2)$，均摊代价为 $O(n)$。但这个分析是有问题的，因为它忽略了弹出操作依赖于之前的压入操作这一事实。

精细分析的关键在于：**任何一个对象，在被压入栈后，至多被弹出一次**。因此，在整个 $n$ 次操作序列中，不断是 $\text{Pop}$ 还是 $\text{Multipop}$，其内部调用弹出操作的次数，不可能超过 $\text{Push}$ 操作执行的次数，即至多为 $n$。所以，最坏情况下的总代价 $T(n) \le 2n = O(n)$。那么，每个操作的均摊代价就为 $T(n)/n = O(1)$。

##### 二进制计数器分析

考虑一个从0开始计数的 $k$ 位二进制计数器，其数值 $x = \sum_{i=0}^{k-1} A[i] \cdot 2^i$，其中 $A[0]$ 是最低位。我们考虑执行 $n$ 次 $\text{Increment}$ 操作，每次操作的代价定义为翻转的位数（0变1或1变0计为一次操作）。

要计算总代价 $T(n)$，我们需要精细分析每一位的翻转规律。观察可知，$A[0]$ 每次操作都翻转，翻转 $n$ 次；$A[1]$ 每2次操作翻转一次，翻转 $n/2$ 次；$A[2]$ 每4次操作翻转一次，翻转 $n/4$ 次。依此类推，对于 $i = 0, 1, ..., \lfloor \lg n \rfloor$，$A[i]$ 的翻转次数为 $n / 2^i$。对于 $i > \lg n$ 的位，由于计数器最大值不超过 $n$，它们始终保持为0，不发生翻转。

因此，总翻转次数 $T(n) = \sum_{i=0}^{\lfloor \lg n \rfloor} \frac{n}{2^i} < n \sum_{i=0}^{\infty} \frac{1}{2^i} = 2n$。这表明 $T(n) = O(n)$。执行了 $n$ 次操作，所以每次 $\text{Increment}$ 操作的均摊代价为 $T(n)/n = O(1)$。

#### 记账法

记账法的核心思想是：为不同类型的操作预先分配一个**摊还费用（可能高于或低于实际代价）**。对于便宜的操作，我们多收一些费用，并将多收的部分作为“信用”存储起来。当昂贵的操作发生时，就用之前积累的信用来支付不足的部分。必须保证在任何时刻，累计的信用金额都不能为负（不能“透支”）。

##### 栈操作分析

首先定义实际代价：$\text{Cost}(\text{Push}) = 1$，$\text{Cost}(\text{Pop}) = 1$，$\text{Cost}(\text{Multipop}) = \min(k, s)$。
然后定义摊还代价：
*   $\text{Cost}_{\text{amortized}}(\text{Push}) = 2$
*   $\text{Cost}_{\text{amortized}}(\text{Pop}) = 0$
*   $\text{Cost}_{\text{amortized}}(\text{Multipop}) = 0$

这种设定的逻辑是：每个元素在入栈时，预先支付了自己未来被弹出时的开销。入栈时的实际开销为1，我们收了2，多出的1元作为信用“存”在这个元素上。当该元素将来被弹出时（无论是通过 $\text{Pop}$ 还是 $\text{Multipop}$），它的摊还代价为0，因为它已经用自己身上存储的1元信用支付了弹出的开销。因为弹出操作的数量不超过入栈操作的数量，所以整个系统不会出现信用为负的情况。因此，对于 $n$ 个操作的序列，总摊还代价最多为 $2n = O(n)$，每个操作的摊还代价为 $O(1)$。

##### 二进制计数器分析

每次 $\text{Increment}$ 操作的成本源于位的翻转。我们定义摊还代价：只要将某一位置为1，就收取2元费用。1元用于支付本次置1的开销，另1元存储在该位上，作为信用。当这一位将来被置为0时，其开销就用之前存储的1元信用来支付，所以置0操作的摊还代价为0。
*   由于计数器初始时全是0，且每次 $\text{Increment}$ 操作至多只会将一个0变成1，所以它实际的置1开销和预存的信用总额是可控的。
*   当发生一连串翻转时，比如 `...0111` 加1变成 `...1000`，这一瞬间消耗了之前三位 `1` 上积累的信用。因为新的 `1` 又会被存入2元，系统始终保持平衡。因此，每次 $\text{Increment}$ 的摊还代价为 $O(1)$，$n$ 次操作总摊还代价为 $O(n)$。

#### 势能法

势能法可以看作是记账法的一种更通用的形式。它不再追踪每块钱的信用，而是将整个数据结构当前积累的“信用”用一个**势能函数** $\Phi(D)$ 来表示，其中 $D$ 代表数据结构的一个状态。势能函数描述了系统在当前状态下“储存的能量”。

设第 $i$ 次操作的实际代价为 $C_i$，它将数据结构从状态 $D_{i-1}$ 变为 $D_i$。那么，这次操作的**摊还代价** $\alpha_i$ 定义为：
$$\alpha_i = C_i + \Phi(D_i) - \Phi(D_{i-1})$$
这可以理解为：真实花费 + 存入/取出余额的变化。如果 $\Phi(D_i) - \Phi(D_{i-1}) > 0$，说明操作使系统势能增加（存钱了）；反之则说明势能减少（花钱了）。
为了保证总摊还代价是总实际代价的上界，我们通常要求初始势能 $\Phi(D_0) = 0$，并且任何时刻势能非负，即 $\Phi(D_i) \ge 0$。这样，对所有操作的摊还代价求和，可以消去中间项：
$$\sum_{i=1}^{n} \alpha_i = \sum_{i=1}^{n} C_i + \Phi(D_n) - \Phi(D_0) \ge \sum_{i=1}^{n} C_i$$

##### 栈操作分析

定义栈 $D$ 的势能函数 $\Phi(D)$ 为栈中元素的个数。
*   **$\text{Push}$**：实际代价 $C_i = 1$。势能变化：$\Phi(D_i) - \Phi(D_{i-1}) = (s+1) - s = 1$。摊还代价 $\alpha_i = 1 + 1 = 2$。
*   **$\text{Pop}$**：实际代价 $C_i = 1$。势能变化：$\Phi(D_i) - \Phi(D_{i-1}) = (s-1) - s = -1$。摊还代价 $\alpha_i = 1 - 1 = 0$。
*   **$\text{Multipop}$**：设实际弹出 $k'$ 个元素，则 $C_i = k'$。势能变化：$\Phi(D_i) - \Phi(D_{i-1}) = (s-k') - s = -k'$。摊还代价 $\alpha_i = k' - k' = 0$。

所有操作的摊还代价均为常数，总摊还代价为 $O(n)$。势能函数“栈中元素个数”准确地衡量了“未来要支付的弹出操作”的总量。

##### 二进制计数器分析

定义计数器 $D$ 的势能函数 $\Phi(D)$ 为其中1的个数 $b_i$。设第 $i$ 次操作需要翻转的最低连续1的个数为 $t_i$。
*   **一般情况**：实际代价 $C_i = t_i + 1$（将 $t_i$ 个1变为0，1个0变为1）。势能变化：消失 $t_i$ 个1，产生1个新1，所以 $\Delta\Phi = 1 - t_i$。摊还代价 $\alpha_i = (t_i+1) + (1-t_i) = 2$。
*   **溢出情况**：$C_i = k$。所有位变0，$t_i$ 个1消失，所以 $\Delta\Phi = -k$。摊还代价 $\alpha_i = k + (-k) = 0$。

摊还代价始终不超过2，因此总摊还代价为 $O(n)$。势能“1的个数”衡量了“潜在将要变为0的位数”。

#### 动态表扩张分析

动态表是一种常见的数据结构，当表满时进行扩容，分配一个更大的表并复制原有元素。通常采用倍增策略（如分配一个大小是原来两倍的新表）。对动态表的插入操作进行均摊分析。假设插入第 $i$ 个元素，如果表未满，实际代价为1；如果表满需要扩容（设当前表大小为 $m$），则复制 $m$ 个元素并插入新元素，实际代价为 $m+1$。如果使用势能法，可以定义一个巧妙的势能函数：$\Phi(T) = 2 \cdot \text{num}[T] - \text{size}[T]$，其中 $\text{num}[T]$ 是当前元素个数，$\text{size}[T]$ 是表的容量。
*   **不扩容**：势能变化 $\Delta\Phi = [2(m+1) - m] - [2m - m] = 2$。所以摊还代价 $\alpha_i = 1 + 2 = 3$。
*   **扩容**：设插入前表满，有 $\text{num} = \text{size} = m$。实际代价 $C_i = m+1$。扩容并插入后，$\text{num} = m+1$，$\text{size} = 2m$。势能变化 $\Delta\Phi = [2(m+1) - 2m] - [2m - m] = 2 - m$。摊还代价 $\alpha_i = (m+1) + (2 - m) = 3$。

无论是否扩容，每次插入的摊还代价都是常数 $O(1)$。这完美诠释了势能函数的作用：当表变满时，势能增加（持续存钱）；当扩容发生时，积累的高势能瞬间释放，支付了复制元素的昂贵开销。

### 哈希

哈希算法是算法和数据结构领域中的一个基础而强大的分支，其目标是从一个键出发，快速找到对应的值。不同于密码学哈希，数据结构中的哈希更关注的是如何快速、均匀地将一个巨大的键空间映射到一个较小的有限范围内，并有效解决映射中产生的冲突。

#### 构建字典的基本方法

我们面临的问题非常普遍：从100万个学生信息中查询学号，或根据手机号找联系人，都是从一个键出发查找一个值。这是典型的字典问题，支持 $\text{Search}$， $\text{Insert}$， $\text{Delete}$， $\text{Member}$ 等操作。传统的实现方式及其性能如下：
*   **未排序数组**：$\text{Search}$ 是 $O(n)$，$\text{Insert}$ 是 $O(1)$，$\text{Delete}$ 是 $O(n)$。
*   **排序数组**：$\text{Search}$ 是 $O(\log n)$（二分查找），但 $\text{Insert}$ 和 $\text{Delete}$ 是 $O(n)$。
*   **平衡二叉搜索树**：所有操作均为 $O(\log n)$。

我们追求的是所有操作都是 $O(1)$ 的理想性能。直接寻址（Direct Addressing）可以做到，但前提是键空间小且连续（如学号0~9999）。当键空间巨大或稀疏时（如手机号、URL、邮箱地址），直接寻址会浪费巨大的内存空间，不可行。

哈希的核心思想便是用一种映射方法，将巨大的、不连续的键空间 $U$，通过一个哈希函数 $h$ 压缩映射到一个较小的数组 $T$ 的范围内。这必然带来一个问题：**冲突**，即 $h(k_1) = h(k_2)$ 但 $k_1 \neq k_2$。哈希算法的关键就在于如何优雅地解决冲突。

#### 解决冲突的方法

##### 链地址法（拉链法）

链地址法通过一个链表将映射到同一个槽位的所有记录链接起来。插入时通常采用头插法，即在链表的最前端插入新元素。在**最坏情况下**，如果所有键都映射到同一个槽位，则一次查找会退化到 $O(n)$。因此，我们需要考虑其**平均情况下的性能**。

我们假设存在一个**简单均匀哈希函数**，即每个键 $k$ 等概率地、独立地映射到 $m$ 个槽位中的任意一个。定义**负载因子** $\alpha = n/m$，表示每个槽的平均键数。
*   **不成功的查找**：需要遍历整个链表，期望开销为 $O(1 + \alpha)$。
*   **成功的查找**：分析相对复杂。设元素插入顺序为 $x_1, x_2, ..., x_n$。查找 $x_i$ 时，排在它前面的元素仅是在它之后插入且与之冲突的元素。利用指示器随机变量和均匀哈希的性质，可推导出成功查找的期望开销也为 $O(1 + \alpha)$。

因此，只要 $\alpha = O(1)$，即 $n = O(m)$，链地址法就能保证 $O(1)$ 的查找性能。

##### 开放寻址法

开放寻址法与链地址法不同，它不使用哈希表之外的存储空间。当发生冲突时，它会在哈希表内部系统地探查，直到找到一个空槽。在这种方法中，哈希函数不仅取决于键 $k$，还取决于探查次数 $i$，形式为 $h(k, i)$。其探查序列 $<h(k,0), h(k,1), ..., h(k, m-1)>$ 应该是 $0, 1, ..., m-1$ 的一个排列。
*   **线性探查**：$h(k, i) = (h'(k) + i) \bmod m$。实现简单，但有**主聚类**问题：连续占用的槽位会形成长块并越长越长，导致平均查找时间急剧增加。
*   **二次探查**：$h(k, i) = (h'(k) + c_1 i + c_2 i^2) \bmod m$。比线性探查好，但有**二次聚类**问题：初始探查位置相同的两个键，其整个探查序列都将完全相同。
*   **双重哈希**：$h(k, i) = (h_1(k) + i \cdot h_2(k)) \bmod m$。这是最接近理想均匀哈希的方法。它不仅让键决定起点，也让键决定探查步长，从而有效地规避了聚类问题。为了使得探查序列能够遍历整个哈希表（保证能找到空位），步长 $h_2(k)$ 必须与表大小 $m$ **互质**。

我们同样可以在**均匀哈希**的假设下分析开放寻址法的性能，即假设每个键的探查序列等概率地是 $m!$ 种可能排列中的任意一种。对于负载因子 $\alpha = n/m < 1$：
*   **一次不成功的查找**：期望探查次数至多为 $1/(1-\alpha)$。
*   **一次成功的查找**：期望探查次数至多为 $\frac{1}{\alpha} \ln\frac{1}{1-\alpha}$。

这意味着，当 $\alpha$ 为常数时（如 $\alpha=0.5$ 时，不成功查找期望探查2次），开放寻址法能够提供 $O(1)$ 的常数时间性能。若 $\alpha$ 接近1（如 $\alpha=0.9$），性能会急剧下降到10次。

#### 哈希函数的构造

一个好的哈希函数应满足**均匀性**，即关键字分布中的规律性不应影响映射的均匀性，相近的关键字也应被映射到相去甚远的位置。
*   **取余法**：$h(k) = k \bmod m$。**绝不要选择有较小除数 $d$ 的 $m$**。例如，如果 $m$ 为偶数，所有偶数键都只会映射到偶数槽位上，导致一半槽位空闲而另一半拥挤。一个较好的实践是选择 $m$ 为一个**素数**，且不应过于接近2的幂次。
*   **乘法散列法**：$h(k) = \lfloor m (kA \bmod 1) \rfloor$。它选择一个常数 $A \in (0, 1)$（如黄金分割数的倒数 $(\sqrt{5}-1)/2 \approx 0.618$），用键值乘以 $A$，取其小数部分，再乘以表长 $m$ 并向下取整。此方法的优点在于 $m$ 的选择不必为素数，并且在计算机里可以通过将 $A$ 表示为定点数，通过快速的定点数乘法和位运算来实现，无需浮点运算，计算高效。

##### 现代哈希算法：MurmurHash

现代哈希函数（如MurmurHash, CityHash, XXHash）致力于在速度和分布均匀性之间取得更好的平衡，并更好地利用现代硬件特性。MurmurHash（意为“模糊捣碎”）的目标是在高性能、分布均匀和低碰撞率之间取得平衡，它不追求密码学安全，因此速度极快。其核心是通过三个操作让输入产生**雪崩效应**（输入中任意1个bit的改变，会导致输出中大约50%的bit发生变化）:
1.  **乘法**：通过乘以常数并利用进位和移位副本叠加，让单bit的影响扩散到多个位置。
2.  **移位/旋转**：重新排列bit，让高、低位进入不同位置参与下一轮混合。
3.  **异或**：将不同来源的信息合并，消除相关性。

MurmurHash的处理流程是：将输入分块，对每一块循环执行乘法、旋转、再乘法、异或到状态、移位等操作，最后再对整个状态进行一次最终的混合，以增强雪崩效应。

#### 动态哈希与应用层优化

实际工程中的哈希表（如Java的HashMap）还需要考虑动态性。随着元素的插入，负载因子 $\alpha$ 会增大，导致性能下降。因此，当 $\alpha$ 超过某个**阈值**时（Java HashMap默认为0.75），就会触发**动态扩容**（通常容量翻倍），并将所有旧元素**重新哈希**到新表中。扩容操作本身很昂贵（$O(m)$），但通过均摊分析可知，连续的插入操作序列总代价依然是 $O(n)$，每次插入的均摊代价为 $O(1)$。

Java的HashMap巧妙地利用了容量始终为2的幂这一特性，使得扩容后的重新哈希变得极其高效。元素的旧位置和新位置之间存在确定关系：新位置要么是原位置，要么是原位置加上旧容量。判断方法只需检查新增的那一个hash bit是0还是1。

即便算法复杂度为 $O(1)$，仍需从硬件和工程层面进行优化，以提升实际性能：
*   **缓存命中**：开放寻址法使用连续内存，具有更好的缓存局部性，而链地址法节点分散，可能导致更多缓存未命中。
*   **减少探查距离**：Robin Hood哈希通过“劫富济贫”的方式，让探查距离长的元素与探查距离短的元素交换位置，从而使所有元素的探查距离更均匀，优化最坏情况下的查找稳定性。
*   **减少比较次数**：现代哈希表（如Swiss Table）使用**元数据/短指纹**技术。它将key的哈希值拆分为两部分：$H_1$ 用于定位，$H_2$ 的少量bit作为“指纹”存储在槽位旁的元数据中。查找时先用SIMD指令并行比较一组槽位的指纹，快速筛选出候选槽，再对极少数候选槽读取完整的key进行比较。这极大地减少了完整key的比较和内存访问开销。

#### 全域哈希

上述哈希都无法规避一个根本性问题：对于任何确定性的哈希函数，总存在一组“坏的”键，使得它们全部映射到同一个槽，导致性能退化为 $O(n)$。攻击者可以利用此点发起哈希DoS攻击。**全域哈希**的思想不是假设输入是随机的，而是**让算法随机选择哈希函数**。

一个哈希函数族 $H$ 若满足：对于任意两个不同的键 $x$ 和 $y$，从 $H$ 中均匀随机选择一个哈希函数 $h$，使得 $h(x) = h(y)$ 的概率不超过 $1/m$，则称 $H$ 为全域哈希函数族。

一种构造全域哈希族的方法依赖于**有限域和模运算**。设 $m$ 为素数，将键 $k$ 分解为以 $m$ 为基的多项式 $k = k_0 + k_1 m + \dots + k_r m^r$。随机选择一个向量 $a = (a_0, a_1, \dots, a_r)$，其中每个 $a_i \in \{0, 1, \dots, m-1\}$。定义哈希函数为：
$$h_a(k) = \left( \sum_{i=0}^{r} a_i k_i \right) \bmod m$$
可以证明，这个哈希函数族是全域的。证明的核心在于：对于任意不同的 $x$ 和 $y$，它们至少在某一位上不同（设第0位不同）。那么当发生碰撞 $h_a(x)=h_a(y)$ 时，$a_0$ 的值将由 $a_1, \dots, a_r$ 唯一确定。由于 $a_1, \dots, a_r$ 有 $m^r$ 种选择，所以导致碰撞的向量 $a$ 共有 $m^r$ 个。而整个函数族的大小为 $m^{r+1}$，因此碰撞概率为 $m^r / m^{r+1} = 1/m$，证毕。

虽然全域哈希在理论上提供了完美的均匀性保证，能抵御恶意输入攻击，但其构造涉及大量的模乘运算，**计算开销太高**，现实中很少直接使用。工程上通常采用**给哈希函数加盐**等方法来达到类似防御效果而无需付出如此高昂的性能代价。
